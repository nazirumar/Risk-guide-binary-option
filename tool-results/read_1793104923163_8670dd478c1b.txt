     2→//
     3→// All money fields use Prisma's `Decimal` type — never Float (rule #1).
     4→// Percentages are also Decimal (e.g. payoutPercent 0.85 = 85% broker payout).
     5→//
     6→// Sandbox/dev uses SQLite. The `Decimal` Prisma type preserves arbitrary
     7→// precision on both SQLite (stored as TEXT) and Postgres (stored as NUMERIC).
     8→// Phase 14's production migration will tighten the precision via a raw SQL
     9→// migration step: money → NUMERIC(18, 2), percentages → NUMERIC(7, 4).
    10→//
    11→// To switch to Postgres: change provider to "postgresql" and point DATABASE_URL
    12→// at your Postgres connection string (see docker-compose.yml).

   318→// ──────────────────────────────────────────────────────────────────────────────
   319→// Session — database-backed session (PROJECT_RULES.md Phase 0 decision: choose
   320→// database sessions, NOT JWT). Database sessions:
   321→//   1. Can be revoked server-side instantly (logout-everywhere, security incident)
   322→//   2. Stolen cookie only contains an opaque ID — no user data leaked
   323→//   3. Every request validates against DB, so revocations take effect immediately
   324→//   4. Pairs cleanly with server actions (need user data anyway)

   718→// Phase 18 — BalanceCheck: a single point-in-time comparison between the

   720→// is resolved one of three ways:
   721→//   MATCHED  — app and broker agreed within tolerance (no adjustment created)

   736→  // choose ADJUST or IGNORE). MATCHED = within tolerance at check time

   739→  // (terminal).
